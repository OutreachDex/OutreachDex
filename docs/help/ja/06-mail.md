# メール

## メールボックスの接続

「設定 → メールアカウント」で追加します：

- **IMAP（受信）**：サーバー、ポート、ユーザー名、パスワードまたはアプリ用パスワード、フォルダ。自動同期と添付ファイルのダウンロードを有効にできます。
- **SMTP（送信）**：サーバー、ポート、送信元アドレスと名前。

Gmail、iCloud、QQ メールなどは通常、メールボックスの設定で「アプリ用パスワード」を生成する必要があり、ログイン用のパスワードは使えません。追加後に「テスト」をクリックして接続を確認できます。パスワードはこのコンピュータで暗号化して保存され、ワークスペースのファイルには書き込まれません。

## 同期と振り分け

- 「メール」ページで「今すぐ同期」をクリックするか、自動同期を有効にします。依頼すれば Agent も同期できます。
- 送信者または受信者が連絡先のメールチャネルと一致するメールは、その人のやり取りに自動で入ります。
- まだ振り分けられていないメールは、「連絡先に振り分け…」で該当する人を選びます。そのアドレスはその人の連絡チャネルに追加され、以後のメールは自動で照合されます。
- 各メールはワークスペースの `mail/` 以下に Markdown ファイルとして保存されます。開いて読んだり注釈を付けたりできます。再同期しても注釈は上書きされません。

## バウンス、配信停止、自動返信の自動認識

同期時に、ヘッダーとキーワードから 3 種類のメールを認識します（モデルは使いません）：

| メール | 処理 |
|---|---|
| **バウンス**（mailer-daemon などからの配信失敗通知） | 失敗したアドレスを「連絡しない」リスト（`suppression.txt`）に追加し、そのアドレス宛ての送信待ちの下書きを破棄し、連絡先のやり取りに「バウンス」を記録 |
| **相手が連絡の停止を希望**（「もう連絡しないでください」「配信停止」「STOP」など） | アドレスを「連絡しない」リストに追加し、ステージを「連絡しない」に変更し、この人の送信待ちの下書きを破棄し、やり取りに説明を残す |
| **自動返信 / 不在** | 記録のみ。返信とはみなさず、ステージも変えず、「あなたの返信待ち」にも表示しない |

誤って認識された場合は手動で対応します：`suppression.txt` からアドレスを削除し、人物ページでステージを戻します。

## 受信メールの意向を判断

やり取りで、受信メールの横にある「Agent に返信させる」をクリックします。右側の Agent が相手の意向（興味あり、質問がある、日程を調整したい、今は都合が悪い、興味なし…）を判断して根拠を説明し、レビュー待ちの返信を保存します。メールの内容はデータとしてのみ扱われ、指示として実行されることはありません。自動で返信、送信、ステージ変更をすることはありません。
