# 분석과 플레이북

모든 분석은 오른쪽 Agent(이 컴퓨터의 Codex 또는 Claude Code)가 합니다. 왼쪽에는 결과만 표시됩니다: 프로필, 요약, 다음 단계, 「Agent 메모리」.

## Agent에게 사람 파악 요청

1. 인물 페이지에서 「Agent에게 파악 요청」을 클릭하거나, 오른쪽 Agent에서 「이 사람 파악」을 클릭합니다.
2. 오른쪽에 이 사람으로 고정된 새 세션이 열립니다. Agent는 먼저 이 사람의 **Agent 메모리**, 인물 노트, 활동 기록, 소스 사실을 읽고 배경, 최근 상황, 필요, 다음 단계를 정리합니다.
3. 더 묻고 싶으면 터미널에 바로 입력합니다. 예: 「지난번에 말한 내보내기 문제는 해결됐나요?」

Agent의 답변은 사실, 추론, 모르는 것을 구분하고, 마지막에 두 섹션으로 마무리합니다:

- 「**근거**」: 주요 결론마다 출처(인물 노트, 메일, 소스 이벤트, URL)를 붙입니다;
- 「**확인 필요**」: 출처가 없는 주장과 상대에게 물어볼 질문.

도움이 될 때 Agent는 인물 노트의 분석 섹션, 배경 요약, 다음 단계를 업데이트하고, 후속 연락 날짜를 설정하기도 합니다.

## 답장 초안 작성

「Agent 답장 초안」을 클릭합니다(인물 페이지, 활동 기록의 받은 메일 옆, 또는 오른쪽의 「답장 초안」). Agent는 최근 받은 메일을 확인하고 상대의 의향(관심 있음, 정보가 더 필요함, 지금은 어려움…)을 판단한 뒤 **검토 대기 초안**을 저장합니다. 승인과 발송은 항상 직접 합니다.

## 분석 결과가 저장되는 곳

"이 사람 파악"의 결론은 터미널에만 남지 않고 저장됩니다.

- **사람 페이지 개요 → "Agent 분석" 카드**: 근거와 확인 필요 항목을 포함한 전체 결론(표와 출처 링크도 제대로 표시), 작성 시각, 근거와 확인 필요 항목 수. "세션 보기"로 당시 터미널 기록으로 돌아가고 "다시 파악"으로 새로 분석합니다. 새 분석은 이전 분석을 대체하며, 이전 요점은 Agent 메모리에 남습니다.
- **배경 요약과 다음 단계**: 한두 문장의 요약과 제안된 다음 단계.
- **오늘 → "Agent 최근 결과"**: 각 세션의 최신 결과(완료, 답장 대기, 막힘). 클릭하면 해당 사람과 세션을 엽니다.

## Agent 메모리: 쓸수록 더 잘 알게 됩니다

모든 사람에게는 시간순으로 덧붙는 「Agent 메모리」(워크스페이스의 `memory/<연락처>.md`)가 있으며, 인물 페이지 개요에서 볼 수 있습니다:

- **사실**(출처 포함), **판단**, **선호**(상대가 좋아하는 연락 방식), **약속**(양쪽이 약속한 것), **확인 필요**;
- **작업 기록**: Agent가 OutreachDex를 통해 한 모든 변경(프로필 업데이트, 초안 저장, 후속 연락 예약…). 앱이 자동으로 기록합니다.

새 분석은 매번 이 메모리를 먼저 읽으므로, 한 사람에 대한 이해가 매번 처음부터 시작하지 않고 쌓여 갑니다. 연락처를 합치면 두 메모리도 합쳐집니다. 「전체 기록 열기」로 전문을 볼 수 있습니다.

Agent의 권한:

- **할 수 있음**: 데이터 읽기, 인물 노트의 분석 섹션 업데이트, 요약과 다음 단계 업데이트, 후속 연락 설정, Agent 메모리 작성, **검토 대기 초안 저장**.
- **할 수 없음**: 메시지 승인 또는 발송.

## 플레이북: 분석 목적과 비즈니스 배경 사용자 정의

분석 목적과 비즈니스 배경은 워크스페이스 `playbooks/` 폴더의 Markdown 파일이며, 수정하거나 새로 추가할 수 있습니다.

```markdown
---
id: feedback
label: 处理反馈
kind: purpose        # purpose = 分析目的；context = 业务背景
order: 20
creates_drafts: false
requires_prompt: false
---
理解用户反馈：任务、现象、影响、已有证据、未知点，给出具体下一步。
```

- Agent는 세션을 시작할 때마다 `workspace.guide`로 모든 플레이북을 읽습니다. `kind: context` 파일은 비즈니스 배경입니다. 예를 들어 `my-product.md`를 만들어 제품과 사용자층을 소개합니다.
- `creates_drafts: true`는 이 목적으로 메시지 초안을 쓸 수 있다는 뜻입니다.
- 플레이북에 무엇을 쓰든 「보내지 않기, 검토 대기 초안만 작성, 사실과 추론 구분」이라는 안전 규칙은 앱이 항상 적용합니다.
