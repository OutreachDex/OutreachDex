# 메일

## 메일함 연결

「설정 → 메일 계정」에서 추가합니다:

- **IMAP(받는 메일)**: 서버, 포트, 사용자 이름, 비밀번호 또는 앱 비밀번호, 폴더. 자동 동기화와 첨부 파일 다운로드를 켤 수 있습니다.
- **SMTP(보내는 메일)**: 서버, 포트, 보내는 주소와 이름.

Gmail, iCloud, QQ 메일 등은 보통 메일함 설정에서 「앱 비밀번호」를 만들어야 하며, 로그인 비밀번호는 쓸 수 없습니다. 추가한 뒤 「테스트」를 클릭해 연결을 확인할 수 있습니다. 비밀번호는 이 컴퓨터에 암호화되어 저장되며 워크스페이스 파일에는 기록되지 않습니다.

## 동기화와 분류

- 「메일」 페이지에서 「지금 동기화」를 클릭하거나 자동 동기화를 켭니다. 요청하면 Agent도 동기화할 수 있습니다.
- 보낸 사람이나 받는 사람이 연락처의 이메일 채널과 같은 메일은 그 사람의 활동 기록에 자동으로 들어갑니다.
- 아직 분류되지 않은 메일은 「연락처로 분류…」에서 해당 사람을 고릅니다. 그 주소는 그 사람의 연락 채널에 추가되고, 이후 메일은 자동으로 매칭됩니다.
- 각 메일은 워크스페이스 `mail/` 아래에 Markdown 파일로 저장됩니다. 열어서 읽고 메모를 달 수 있으며, 다시 동기화해도 메모는 덮어쓰지 않습니다.

## 반송, 수신 거부, 자동 답장 자동 인식

동기화할 때 헤더와 키워드로 세 종류의 메일을 인식합니다(모델은 쓰지 않습니다):

| 메일 | 처리 |
|---|---|
| **반송**(mailer-daemon 등이 보낸 배달 실패 알림) | 실패한 주소를 「연락 안 함」 명단(`suppression.txt`)에 추가하고, 이 주소로 보낼 초안을 폐기하며, 연락처 활동 기록에 「반송」을 남김 |
| **상대가 연락 중단을 요청**(「다시 연락하지 마세요」「수신 거부」「STOP」 등) | 주소를 「연락 안 함」 명단에 추가하고, 단계를 「연락 안 함」으로 바꾸며, 이 사람의 발송 대기 초안을 폐기하고, 활동 기록에 설명을 남김 |
| **자동 답장 / 부재중** | 기록만 함. 답장으로 치지 않고, 단계를 바꾸지 않으며, 「내 답장 대기」에도 나타나지 않음 |

잘못 인식되었다면 직접 처리합니다: `suppression.txt`에서 주소를 지우고, 인물 페이지에서 단계를 되돌립니다.

## 받은 메일의 의향 판단

활동 기록에서 받은 메일 옆의 「Agent에게 답장 요청」을 클릭합니다. 오른쪽 Agent가 상대의 의향(관심 있음, 질문 있음, 시간을 잡고 싶음, 지금은 어려움, 관심 없음…)을 판단하고 근거를 설명한 뒤 검토 대기 답장을 저장합니다. 메일 내용은 데이터로만 다뤄지며 지시로 실행되지 않습니다. 자동으로 답장하거나, 보내거나, 단계를 바꾸지 않습니다.
