# 分析与 Playbook

所有分析都由右侧的 Agent 完成（你本机的 Codex 或 Claude Code）。左侧只展示结果：资料、摘要、下一步和「Agent 记录」。

## 让 Agent 了解一个人

1. 在人物页点「让 Agent 了解」，或在右侧 Agent 点「了解此人」。
2. 右侧会新建一个固定针对这个人的会话。Agent 先读这个人的 **Agent 记录**、档案、往来记录和来源事实，再总结背景、近况、需求和下一步。
3. 想继续问，直接在终端里输入，例如「她上次说的导出问题解决了吗？」。

Agent 的回答区分事实、推断和未知，并以两段收尾：

- 「**依据**」：每条主要结论附上来源（档案、邮件、来源事件或网址）；
- 「**待确认**」：没有来源的说法和需要问对方的问题。

有用时，Agent 会更新档案的分析章节、背景摘要和下一步，也可能设置跟进日期。

## 起草回复

点「Agent 起草回复」（人物页、往来记录里的来信旁，或右侧的「起草回复」）。Agent 会核对最近来信，判断对方意向（感兴趣、要更多信息、现在不方便……），然后保存一份**待审核草稿**。批准和发送始终由你来做。

## 分析结果存在哪里

每次「了解此人」的结论都会存下来，而不只留在终端里：

- **人物页概览 →「Agent 分析」卡片**：完整结论（含「依据」「待确认」，表格和来源链接都能正常显示），标出写于什么时候、依据和待确认各几条。点「查看会话」回到当时的终端记录，点「重新了解」再分析一次。新的分析会替换旧的，旧的要点仍保留在 Agent 记录里。
- **背景摘要和下一步**：一两句话的摘要和建议的下一步。
- **今日 →「Agent 最近的结果」**：每个会话最近的结果（已完成、等你回复、受阻），点一条就打开对应的人和会话。

## Agent 记录：越用越了解

每个人都有一份按时间追加的「Agent 记录」（工作区 `memory/<联系人>.md`），在人物页概览里可以看到：

- **事实**（附来源）、**判断**、**偏好**（对方喜欢的联系方式）、**约定**（双方答应的事）、**待确认**；
- **操作流水**：Agent 通过 OutreachDex 做过的每次修改（更新资料、保存草稿、设置跟进……），由应用自动记下。

每次新的分析都会先读这份记录，所以对一个人的了解会一次次积累，而不是每次从零开始。合并联系人时，两份记录会合在一起。点「打开完整记录」可以查看全文。

Agent 的权限：

- **可以**：读资料、更新档案里的分析章节、更新摘要和下一步、设置跟进、写 Agent 记录、**保存待审核草稿**。
- **不可以**：批准或发送任何消息。

## Playbook：自定义分析目的和业务背景

分析目的和业务背景都是工作区 `playbooks/` 目录里的 Markdown 文件，可以修改，也可以新增。

```markdown
---
id: feedback
label: 处理反馈
kind: purpose        # purpose = 分析目的；context = 业务背景
order: 20
creates_drafts: false
requires_prompt: false
---
理解用户反馈：任务、现象、影响、已有证据、未知点，给出具体下一步。
```

- Agent 在每个会话开始时通过 `workspace.guide` 读取所有 playbook。`kind: context` 的文件是业务背景，例如写一份 `my-product.md`，介绍你的产品和用户群。
- `creates_drafts: true` 表示这个目的可以起草消息。
- 不论 playbook 怎么写，「不发送、只写待审核草稿、区分事实与推断」这些安全规则都会由应用强制加上。
