# 连接数据源

数据源让你的业务后台（比如产品的用户后台、工单系统）把「人」和「事件」交给 OutreachDex。之后你可以看到每个人的套餐、使用情况、反馈，并据此分析和联系。

## 你的后台需要做什么

后台按 **GCSP/1** 规范实现 3 个只读接口：`/manifest`、`/people`、`/events`，并签发一个只读 token。完整规范见项目的 `docs/gcsp.md`，也有 Go 和 Node 的参考实现。开发者可以先用命令行自测：

```sh
globalcontact source check https://你的后台/gcsp --token <token>
```

## 连接

1. 打开「来源」页 → 连接来源。
2. 填写来源地址和 token；请求头默认是 `Authorization`，后台用别的请求头时再修改。
3. 点「检查」：应用会逐项检查接口是否符合规范，并预览前几个人。
   - **失败**项必须让后台修正；
   - **警告**项可以先连接，建议后台之后修正。
4. 点「连接并同步」。之后会按设定间隔（默认 60 分钟）自动增量同步，也可以随时点「立即同步」。

地址必须是 `https://`（本机调试可以用 `http://127.0.0.1`）。token 加密保存在本机。OutreachDex 只调用只读接口，不会向后台写任何数据。

## 身份匹配

同步来的每个人，按以下规则对应到联系人：

| 情况 | 结果 |
|---|---|
| 后台已验证的邮箱与某个联系人一致 | **自动关联** |
| 邮箱一致，但后台没有验证 | 进入「**待确认**」，由你判断是不是同一人 |
| 没有匹配 | 留在「**未关联**」，可以「建为联系人」或「关联到…」已有联系人 |

- 同名永远不会自动合并。
- 你选「不是」之后，重新同步也不会再提示。
- 关联后，这个人的来源事件会补进往来记录，来源邮箱加入联系渠道。

## 了解还不是联系人的用户

在「来源」页点任意一个人（包括未关联的），可以看到他在来源里的事实、属性变化和事件，点事件可以打开原文。点「让 Agent 了解」，右侧 Agent 会读取这些资料，概括他的使用阶段、付费、遇到的问题和活跃度，并判断现在是否值得联系，不需要先建为联系人。值得联系时，再「建为联系人」并起草。

Agent 也可以直接搜索所有来源用户，例如问它「哪些免费用户积分用完了但最近还在用？」。

## 来源事实

已关联的人，在人物页的「来源事实」卡片里显示后台提供的属性，例如套餐、积分、注册时间，并标注来源和同步时间。后台标为个人信息的属性会特别标注。只有后台在 manifest 里声明过的属性才会被保存。

## 变化记录

每次同步时，OutreachDex 会对比这个人的属性，把变化记下来，例如「套餐：free → pro」「剩余积分：20 → 0」。

- 人物页「来源事实」卡片里点「变化记录」查看最近的变化。
- 完整记录保存在工作区 `sources/<来源>/people/<编号>.md`：上面是当前属性，下面是带时间的变化日志，可以直接打开阅读或交给 Agent 分析。
- 只记录后台在 manifest 里声明过的属性。

## 新联系人的语言

从来源建的联系人会带上语言，Agent 按联系人语言起草。顺序是：来源给出的这个人的语言 → 来源「…」菜单里的「新联系人语言」→ 来源声明的默认语言 → 工作区默认。ThumbnailSnap 这类英文站点，建议把「新联系人语言」设为 English。草稿语言和联系人语言对不上时，审核界面会提示。
