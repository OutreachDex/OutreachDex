# 名单与冷联

名单帮你从联系人和数据源里找出**现在值得联系的人**：先由助手逐个调研、起草，再由你逐个审核。发送始终由你决定，**不会群发，也不会自动发送**。

## 新建名单

在「名单」页点 ＋，填写：

- **名称和目的**：目的会告诉助手为什么联系这些人，例如「了解卡在哪里，是否需要帮助」。
- **候选人来自**：已有联系人，或某个数据源里的人（包括还没关联的人）。
- **渠道、分析目的、业务背景**。渠道可选邮件、X、Instagram、微信、WhatsApp、TikTok、Facebook / Messenger、LinkedIn 或其他；只有邮件由应用发送，其余渠道的草稿复制后自己发送，再「标记已发」。
- **筛选条件**（必须全部满足）：
  - 来源属性：例如 套餐 = free、剩余积分 ≤ 0；
  - 事件：例如 30 天内有「积分用完」、没有「购买积分」；
  - 事件次数：例如 14 天内「任务失败」至少 2 次、「购买积分」正好 0 次（天数留空表示全部时间）；
  - 联系状态：阶段、从未联系、上次联系超过 N 天；
  - 联系人字段：例如项目、单位。

编辑时会实时显示符合条件的人数和前几位。「不再联系」的人会被自动排除。名单保存在工作区 `lists/` 目录。

## 批量准备

勾选部分人或直接点「批量准备」，这些人会排队，并交给右侧 Agent **一个一个**处理（每一步都显示在终端里）：

1. 来源里还没关联的人，先建为联系人；
2. 核实入选依据（来源事实和往来记录）；
3. 如果现在联系确实对对方有帮助，起草一份待审核消息，开头说明为什么现在联系；资料不足就不起草，并在成员表里写明原因。

准备会使用你本机登录的 Claude Code / Codex，消耗你的模型额度。Agent 中断后，点名单上方的「让 Agent 继续」接着处理；也可以「取消排队」。每个人入选的原因会显示在成员表里。

## 逐个审核

点「逐个审核」：

- 左边是「为什么现在联系」和来源事实，右边是草稿。
- 可选操作：**保存**、**批准并下一位**、**跳过**、**不再联系**。
- 批准不会发送。要发送时，在草稿里点「去发送…」，选择发件账号并确认。

## 防止打扰

- **不再联系**：地址会写入工作区 `suppression.txt`，联系人阶段改为「不再联系」，这份草稿作废。之后所有名单都会排除他，发送也会被拒绝。
- **每日上限**：名单消息每天最多发送的条数（默认 20，邮件和手动标记已发都算），在 `globalcontact.toml` 的 `[outreach] daily_limit` 修改。名单页右上角显示今天已发的数量。
